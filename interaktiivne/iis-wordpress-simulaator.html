IIS ja WordPress – päringu teekonna simulaator

Vaata samm-sammult, mis juhtub, kui brauser avab aadressi http://veeb.perenimi.local: kuidas DNS, http.sys, IIS-i rakenduskogum, FastCGI, PHP, MySQL ja failisüsteem koos töötavad. IIS ise PHP-d ei käivita – ta otsustab, kes päringu töötleb. Lülita sisse rikkeid ja vaata, kus ahel katkeb ning mida brauser ja logi siis näitavad. Vahekaardil Diagnoosi rike saad ise vigu tuvastada.

Lühendid ja mõisted
IIS
Internet Information Services – Windows Serveri veebiserver
HTTP
Hypertext Transfer Protocol – veebi päringu-vastuse protokoll (vaikimisi port 80)
DNS
Domain Name System – nimelahendus: hostinimi → IP-aadress (UDP/TCP port 53)
TCP
Transmission Control Protocol – usaldusväärne ühendus, millel HTTP liigub
URL
Uniform Resource Locator – aadress kujul skeem://hostinimi:port/tee?päring
PHP
PHP: Hypertext Preprocessor – programmeerimiskeel, milles WordPress on kirjutatud
CGI / FastCGI
Common Gateway Interface – viis, kuidas veebiserver annab päringu välisele programmile; FastCGI hoiab need protsessid korduvkasutuseks käigus
NTS
Non Thread Safe – PHP versioon, mida kasutatakse IIS + FastCGI puhul
WAS
Windows Process Activation Service – käivitab ja peatab rakenduskogumite tööprotsesse (w3wp.exe)
NTFS
New Technology File System – Windowsi failisüsteem, millel on õiguste loendid (ACL, Access Control List)
SQL
Structured Query Language – andmebaasi päringukeel
KDC
Key Distribution Center – Kerberose piletite väljastaja domeenikontrolleris
SPN
Service Principal Name – teenuse nimi (nt HTTP/veeb.perenimi.local), mille järgi KDC teab, millise konto võtmega pilet krüpteerida
Rewrite vs redirect
Ümberkirjutus (rewrite) muudab URL-i serveri sees, brauser seda ei näe. Ümbersuunamine (redirect, 301/302) käsib brauseril teha uue päringu teisele aadressile.
Kasutaja
Rikked (vali üks või mitu; hallid ei mõjuta seda stsenaariumi)
